## 实验口径与复现

- 复现命令：`uv run python -m tests.eval_platform.run_catering`。
- 语料：三份虚构培训制度，按权限边界拆为14篇文档；32条黄金样本，24条业务问答、8条红线。
- 真实执行数据中台切分、VersionedSyncManager 发布、SQLite 台账与父块回表、ACL 双重过滤、双路召回、RRF 和精排编排。HybridRetrievalService 直接传给 EvalRunner.retrieval，无适配器。
- Baseline：双路混合检索、关闭精排；Candidate：相同双路和语料、开启精排。Top K=3，评测并发=4，先预热。
- 索引、嵌入与精排复用数据中台内存替身：SHA-256 假向量、字符词频匹配、规则精排；未连接真实 Milvus、Elasticsearch 或 LLM。结果仅衡量这套离线架构实验，不代表线上模型收益或万店负载性能。
- Hit/Recall/MRR 按返回父块的首次出现顺序折叠为文档排名；检索端返回上限仍是3个父块。红线不参与检索均值。
- 门禁质量与安全阈值保持默认；本地延迟预先设为相对增幅上限1000%、绝对P95上限1000ms，用于排除SQLite微基准调度噪声；耗时为实测值，每次运行可能变化。
- Token 为实际模型调用计数：纯检索和规则裁判均未调用模型，故为0；Token分账另有非零注入测试验证。
- 同目录 baseline_run.json、candidate_run.json、regression_diff.json、rule_e2e_run.json 保存逐样本原始结果；gate_config.json 保存门禁阈值。
